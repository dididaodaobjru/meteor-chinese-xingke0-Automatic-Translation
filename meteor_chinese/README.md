# 为 meteor客户端 提供中文支持
目前支持 meteor客户端主体 + 部分 meteor 第三方插件模块

> 当前版本：**1.4.0**，适配 **Minecraft 1.21.11** + Meteor Client 1.21.11-SNAPSHOT

## 汉化覆盖范围
| 位置 | 是否汉化 | 说明 |
|---|---|---|
| 模块名 / 模块描述 | ✅ | 语言文件 + 自动汉化 |
| 设置项名 / 设置项描述 | ✅ | 语言文件 + 自动汉化 |
| 模组分类标签（Combat / Player / Movement / Render / World / Misc） | ✅ | |
| 顶部标签页（Modules / Config / GUI / HUD / Friends / Macros / Profiles / Baritone） | ✅ | 连窗口标题一起 |
| Meteor 界面控件文字（Select / Copy / Search / Bind / Back / Clear ...） | ✅ | 共 65 条内置词条，其余走自动汉化 |
| 聊天栏消息 | ⚠️ | 需要手动开「聊天翻译」 |
| 模块运行时输出、命令帮助文本 | ❌ | 不在覆盖范围 |

## 如何使用
点击 中文翻译支持 模块中的 中文翻译 按钮
右键中文翻译 点击开启翻译即可

> 1.4.0 起「自动翻译」与「启用自动汉化」默认都是**开**的，开启模块就会自动应用并补齐缺失词条，
> 不用再手动点按钮。

## 自动汉化（1.3.0 新增）
内置语言文件覆盖了 1.0 万多条词条，但新装的插件总会有没翻译到的地方。
开启「自动汉化」后，没命中的模块名、描述、设置项会联网自动翻译成中文，并缓存到本地：

`<游戏目录>/meteor-client/meteor-chinese-auto.json`

缓存文件格式和语言文件完全一致，可以直接合并进 `zh_cn.json` 提 PR 给上游。

设置项（模块里的「自动汉化」分类）：
| 设置 | 说明 |
|---|---|
| 启用自动汉化 | 总开关 |
| 翻译源 | `Bing` / `MyMemory` 免费且无需 Key；`OpenAI` 可接 DeepSeek 等兼容接口 |
| API地址 / API Key / 模型 | 仅选 OpenAI 时出现，例如 `https://api.deepseek.com/v1` + `deepseek-chat` |
| 单次上限 | 一次游戏最多翻译多少条，防止免费接口被刷爆（默认 400） |

模块界面上的按钮：「自动汉化」立即扫描并翻译缺失词条，「状态」查看缓存条数/队列/错误，
「清空自动翻译缓存」「重载缓存」用于维护。

> 翻译是后台逐条进行的，首次填充几百条大约需要几分钟。翻译完成的瞬间会自动刷新界面文本，
> 不需要重开游戏。第二次启动直接读缓存，不再联网。

## 聊天翻译（1.3.0 新增）
在模块的「聊天翻译」分类里：

| 设置 | 说明 |
|---|---|
| 收到的消息 | `Off` 关闭；`Merge` 原文与译文合并成一行（默认）；`Append` 原文照常显示、译文另起一行 |
| 发送的消息 | `Off` 关闭；`ZhToEn` 把中文翻成英文再发出；`EnToZh` 把英文翻成中文再发出 |
| 最短长度 | 短于该长度的消息不翻译，避免 gg、+1 这类噪音（默认 4） |
| 发送后提示译文 | 翻译后在自己聊天栏里显示实际发出的内容 |

效果大概是：

```
<Steve> hello everyone        →   <Steve> hello everyone [大家好]
```

原文始终保留可见。翻译失败时会原样显示原文，不会吞消息。命令（以 `/` 开头）不会被翻译。

## 已知问题
1. 翻译均由DeepSeek+豆包等大语言模型进行翻译 部分插件模块翻译效果不佳 （如果你有更好的意见 请反馈给我）
2. 自动汉化依赖公共翻译接口。必应接口偶尔会限流，此时会自动重试一次，仍然失败就保留英文原文，
   不会影响游戏。想要更稳定的质量可以在设置里换成自己的 DeepSeek / OpenAI 兼容接口。
## 为什么启用翻译过后功能名称一片空白或乱码方框符号
1.如果模块名称无法正常显示 请将 meteor客户端 的自定义字体切换为任意支持中文的字体
